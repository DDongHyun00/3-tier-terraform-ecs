# DEC-46. 태스크 사양을 0.25 vCPU / 0.5 GB에서 0.5 vCPU / 1 GB로 올린다

- 상태: 확정 · 날짜: 2026-10-21 · 검증: 실측 완료
- 관련 이슈: https://github.com/DDongHyun00/3-tier-terraform-ecs/issues/29

## 배경

E05에서 태스크를 0.25 vCPU / 0.5 GB로 처음 띄웠더니 앱 기동에 120초가 걸렸다("Started BoardApplication in 120.585 seconds", 로컬 11초). 헬스체크 유예 60초보다 길어서 태스크가 계속 교체됐고, 유예를 임시로 240초로 늘렸다. 사이트도 느렸다. ALB 평균은 0.1~0.2초였지만 최대 2.8~3.9초가 나왔고, 이미지 첨부 글쓰기가 4~5초 걸렸다. 코드를 보니 N+1은 없었다(JOIN FETCH·BatchSize·배치 카운트).

## 결정 요인

- 기동 120초는 재배포·스케일 아웃·장애 복구 시간을 전부 늘린다. E07 오토스케일링과 E08 장애 재현의 수치가 이 값에 묶인다.
- Fargate 요금은 서울 vCPU 0.04656, GB 0.00511 USD/시간이라 2개 기준 시간당 0.028 → 0.057 USD로 2배다(`docs/cost.md`).

## 검토한 선택지

- A. 0.25 vCPU 유지, 유예 240초로 버팀: 비용은 그대로지만 기동 2분과 느린 첫 요청을 감수한다.
- B. 0.5 vCPU / 1 GB + JVM 옵션: 비용 2배, 이미지 재빌드 없이 태스크 정의만 바뀐다.

## 결정

B. `modules/compute/variables.tf`의 `task_cpu` 256→512, `task_memory` 512→1024, 태스크 환경 변수에 `JAVA_TOOL_OPTIONS = "-XX:MaxRAMPercentage=75.0 -XX:TieredStopAtLevel=1"`을 넣었다. 바꾸기 전과 뒤를 같은 명령(`curl -w '%{time_total}'`, 기동 로그)으로 재서 비교했다.

## 결과

10/22 실측:

| 항목 | 0.25 vCPU | 0.5 vCPU |
| --- | --- | --- |
| 앱 기동 | 121.5 / 123.0초 | 23.1 / 23.1초 |
| /posts 첫 요청 → 재요청 | 0.47 → 0.06초 | 0.13 → 0.08초 |
| /login | 0.05초 | 0.06~0.10초 |
| 롤링 배포 | (첫 배포라 비교 불가) | 2분 42초 |

- 얻은 것: 기동 5배 단축(약 122초 → 23초). 이 값 덕분에 E07 스케일 아웃에서 새 태스크가 결정 후 80초 안에 healthy가 됐다.
- 바뀌지 않은 것: 워밍업 뒤 단순 페이지 응답은 둘 다 0.1초 안팎으로 차이가 없었다. 느림의 원인은 CPU가 아니라 기동 직후 JIT·초기화였다.
- 감수한 것: Fargate 비용 2배(시간당 +0.029 USD, 24시간 가동 월 +21.17 USD).
- 못 잰 것: 0.5 vCPU에서 콜드 글쓰기 체감. 전후 글쓰기 측정이 둘 다 같은 0.25 태스크에서 나왔다.
- 결정 10/21, 기록 11/01 소급 작성.
