# DEC-67. 태스크 하나를 Spot으로 돌리고 관측 서버는 끌 수 있게 했다

- 상태: 확정
- 날짜: 2026-11-05

## 배경

세션 비용을 더 줄일 곳을 찾았다. 실제 청구액을 보니 운영 시간 요금은 NAT, ALB, RDS 같은 고정분이 대부분이었다. 손댈 수 있는 건 컴퓨트(온디맨드 t3.small 2대)와 관측 서버(Prometheus와 Grafana, ELK)였다. Well-Architected 비용 원칙의 COST07(중단 가능한 워크로드에 Spot)과 COST09(쓰지 않을 때 끄기)를 여기에 맞췄다.

지킬 조건은 네 가지로 정했다.
- 사용자 요청 실패 0건을 유지한다. 비용을 줄이려고 가용성을 내주지 않는다.
- 표준 기능(용량 공급자, 관리형 드레이닝, FIS)으로만 한다.
- 측정으로 확인할 수 있어야 한다.
- 아무 변수도 넘기지 않는 CI apply는 지금과 같은 구성을 만든다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 전부 Spot | 컴퓨트 비용이 약 75% 준다 | 두 대가 같이 회수되면 서비스가 멈춘다 |
| 온디맨드 1 + Spot 1, 여유 없음 | 컴퓨트 비용이 32% 준다 | 회수 때 대체 서버 기동이 2분을 넘겨 요청이 13~18건 실패했다 |
| 온디맨드 1 + Spot, 대기 Spot 1대와 최소 정상 비율 50% | 회수 때 실패가 0건이었다 | 절감이 15%로 줄고 회수와 배포 때 1~2분은 태스크가 1개다 |
| Warm pool | 기동 시간이 준다 | Spot ASG에서는 쓸 수 없다 |
| Fargate Spot | 인스턴스를 관리하지 않는다 | EC2로 옮긴 이유인 호스트 관측과 맞지 않는다 |

## 결정

- 태스크 2개 가운데 1개만 Spot에 뒀다. 용량 공급자 전략은 온디맨드 `base=1, weight=0`과 Spot `weight=1`이다.
- Spot ASG는 t3.small과 t3a.small 가운데 `price-capacity-optimized`로 고르고, 용량 재조정을 켰다.
- Spot 용량 공급자의 목표 사용률을 50%로 둬서 대기 인스턴스 1대를 늘 유지했다.
- 서비스 최소 정상 비율은 100%에서 50%로 낮췄다.
- 온디맨드 ASG는 2a, Spot ASG는 2c 서브넷만 쓰게 나눴다.
- 관측 서버는 `enable_monitoring`, `enable_logging` 변수로 끌 수 있게 했다. 기본값은 켬이다.

## 결과

- 컴퓨트 시간 요금이 0.059에서 0.050 USD로 15% 줄었다. 관측 서버를 끈 세션은 시간당 0.135 USD(34%)가 준다.
- Spot이 회수돼도 온디맨드 태스크가 남는다.
- FIS로 태스크가 있는 Spot 인스턴스에 회수 예고를 보내고 1초마다 요청하면서, 설정을 하나씩 더해 네 번 쟀다(2026-11-05). 실패는 기본 설정 13건, 용량 재조정 18건, 대기 Spot 12건이었고, 최소 정상 비율 50%를 더하자 0건이 됐다.
- 마지막 설정에서는 예고 25초 뒤 옛 태스크가 대상 그룹에서 빠졌고, 1분 22초 만에 대체 태스크가 정상이 됐다.
- 감수한 것: 대기 인스턴스가 Spot 절감의 절반 가까이를 다시 쓴다. 회수와 배포 때 1~2분 동안 태스크가 1개다. 온디맨드와 Spot이 가용 영역을 하나씩 고정해서 쓴다.
- 회수 측정 기록은 [Spot 회수](../troubleshooting/07-spot-interruption.md), 비용 계산은 [비용](../cost.md)에 있다.
