# DEC-67. 운영 태스크 하나를 Spot에 두고(온디맨드 base 1), 대기 Spot 1대와 최소 정상 비율 50%로 회수를 사용자에게 보이지 않게 넘기며, 관측 서버는 변수로 끌 수 있게 한다

- 상태: 확정 · 날짜: 2026-11-05 · 검증: 실측 완료
- 관련 이슈: https://github.com/DDongHyun00/3-tier-terraform-ecs/issues/46

## 배경

E09 #46에서 세션 비용을 더 줄일 방법을 찾았다. #45 청구액 분석에서 운영 시간 요금은 NAT·ALB·RDS 같은 고정분이 대부분이었고, 손댈 수 있는 변동분은 컴퓨트(온디맨드 t3.small 2대)와 관측 서버(Prometheus/Grafana, ELK)였다. Well-Architected 비용 원칙에서 COST07(중단 가능한 워크로드에 Spot)과 COST09(쓰지 않을 때 끄기)를 찾아 이 둘에 대응시켰다.

## 결정 요인

- 사용자 요청 실패 0건을 유지할 것. 비용을 줄이려고 가용성을 내주지 않는다
- 표준 기능으로만 할 것(용량 공급자, 관리형 드레이닝, FIS)
- 측정으로 확인할 수 있을 것
- CI apply의 기본 구성이 지금과 같을 것

## 검토한 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| 전부 Spot | 컴퓨트 약 75% 절감 | 두 대가 같이 회수되면 서비스 중단 |
| 온디맨드 base 1 + Spot 1 (여유 없음) | 컴퓨트 −32% | 회수 때 대체 서버 기동이 2분을 넘겨 실패 13~18건(실측) |
| 온디맨드 base 1 + Spot, 목표 사용률 50%(대기 Spot 1대) + 최소 정상 비율 50% | 회수 때 실패 0건(실측) | 컴퓨트 절감 −15%로 줄어듦, 회수·배포 때 1~2분 태스크 1개 |
| Warm pool | 기동 시간 단축 | Spot ASG에서 지원하지 않음 |
| Fargate Spot | 인스턴스 관리 없음 | E10에서 EC2로 옮긴 이유(호스트 관측)와 충돌 |

## 결정

태스크 2개 중 1개만 Spot에 두었다. 전략은 온디맨드 `base=1, weight=0` + Spot `weight=1`이다. Spot ASG는 t3.small·t3a.small에 `price-capacity-optimized`, 용량 재조정을 켰고, Spot 용량 공급자 목표 사용률을 50%로 두어 대기 인스턴스 1대를 유지했다. 서비스 최소 정상 비율은 100에서 50%로 낮췄다. 온디맨드 ASG는 2a, Spot ASG는 2c 서브넷만 쓰게 나눴다. 관측 서버는 `enable_monitoring`·`enable_logging` 변수로 끌 수 있게 했다(기본 켬). PR #146, #149~#152.

## 결과

- 얻은 것: 컴퓨트 시간 요금 0.059 → 0.050 USD(−15%), 관측을 끈 세션은 시간당 −0.135 USD(−34%). Spot이 회수돼도 온디맨드 태스크가 남는다
- 감수한 것: 대기 인스턴스가 Spot 절감의 절반 가까이를 쓴다. 회수·배포 때 1~2분 동안 태스크가 1개다. 온디맨드와 Spot이 AZ를 하나씩 고정해 쓴다
- 실측(2026-11-05): FIS `aws:ec2:send-spot-instance-interruptions`로 태스크가 있는 Spot 인스턴스에 회수 예고를 보내고, 1초마다 `/posts`와 liveness를 요청했다. 설정을 하나씩 더하며 네 번 쟀다. 실패는 13건(기본) → 18건(용량 재조정) → 12건(대기 Spot) → 0건(최소 정상 비율 50%)이었다.
- 마지막 설정에서는 예고 25초 뒤 옛 태스크가 대상 그룹에서 빠졌고, 1분 22초 만에 대체 태스크가 healthy가 됐다. 상세는 `docs/cost.md` 10절.
